# Потоковый shadow replay и воспроизводимый benchmark

Это **офлайн-воспроизведение**, а не подключение к оборудованию. Программа
не отправляет пакеты, не меняет маршруты, не выполняет request racing и не
управляет QKD/PTP. Модель обучена на синтетике; метки получены из RTT,
вероятности не объявляются калиброванными. Порог 100 мс — экспериментальная
граница, не обещание SLA и не измеренная характеристика целевых каналов.

## Команды

```bash
# Обучение предупреждений: горизонты 1/5/15/60 измерений
uv run quantum-link warning-experiment --seed 42 --epochs 40 --output artifacts/warning-42
# Обучение и оценка причинного селектора
uv run quantum-link risk-experiment --seed 42 --epochs 40 --scenario normal --output artifacts/risk-42
# Фиксированные веса и конфигурация селектора из checkpoint
uv run quantum-link shadow-replay --model artifacts/risk-42/warning-model.pt --synthetic-input artifacts/risk-42/telemetry.csv --output artifacts/replay-42
# Все шесть заранее объявленных запусков, без подбора по тесту
uv run quantum-link benchmark-suite --seeds 41 42 43 --samples 4000 --epochs 40 --output artifacts/shadow-suite
# Только локальный, ранее полученный JSON RIPE Atlas: один реальный путь
uv run quantum-link atlas-benchmark --input artifacts/realism-audit/atlas-1001-probe-10001.json --output artifacts/shadow-atlas
```

`warning-experiment` сохраняет `warning-model.pt`, `warning-report.json`,
`warning-predictions.csv`, `telemetry.csv`; методика purge и знаменатели описаны
в [протоколе предупреждений](early-warning.md). `risk-experiment` дополнительно
сохраняет `risk-report.json`, `risk-decisions.csv`; целевая функция, hold и
гистерезис описаны в [протоколе выбора](risk-selection.md).

`benchmark-suite` выполняет normal и shared-stress для каждого seed. Во втором
сценарии ко всему ряду до разбиения добавляется 25 мс обоим каналам. В каждом
подкаталоге обучается отдельная модель и выполняется replay сохранённых весов.
Несовпадение решений на любом sample, среднего выбранного RTT (абсолютный
допуск 1e-10 мс) или числа
переключений с пакетной оценкой прерывает suite. Это проверка согласованности,
не статистический тест превосходства. Общий отчёт — `suite-report.json`.
Повторное использование каталога перезаписывает результаты.

## Причинность и журнал

В `shadow.jsonl` сначала записывается и flush-ится `kind=decision`, только затем
потребляется текущий outcome и пишется `kind=evaluation`. Решение содержит
`information_cutoff`, прогноз RTT, вероятности по горизонтам, номер пути либо
null и причину; `network_action` всегда `none_shadow_only`. Фактические RTT,
статусы и oracle находятся только в evaluation. Модель и scaler не изменяются.
Расписание времён известно заранее; это не демонстрация приёма live-потока.
Обёртка читает файл в память, но decision-функция получает только прошлую историю.

Для синтетического ряда replay по умолчанию начинается с сохранённого `val_end`.
Более ранний старт запрещён; SHA-256 префикса train+validation должен совпадать.
Checkpoint хранит provenance, границы, scaler, веса и параметры селектора.
Загружайте только доверенные checkpoint. `shadow-report.json` содержит хеши
входа/модели, coverage, abstentions и метрики с явными знаменателями.

## Внешняя телеметрия

Она не принимается за синтетику. Для диагностического replay нужен явный допуск:

```bash
uv run quantum-link shadow-replay --model artifacts/risk-42/warning-model.pt --telemetry-input data/real.csv --allow-domain-shift --output artifacts/real-shadow
```

Строгий порядок колонок CSV (UTF-8):

```text
sample,timestamp,path,status,rtt_ms,source,provenance
```

- `sample`: неотрицательный последовательный индекс измерения;
- `timestamp`: ISO 8601 с timezone, времена строго возрастают между samples;
- `path`: 0 или 1, не больше одной строки пути на sample;
- `status`: `ok`, `timeout`, `missing`;
- `rtt_ms`: положительное конечное число только при `ok`, иначе пустое поле;
- `source`: `real_telemetry` или `ripe_atlas`, не synthetic;
- `provenance`: непустое описание происхождения, точки/метода измерения.

У путей одного sample должны совпадать timestamp и source. Отсутствующая строка
пути означает missing; второй канал не копируется из первого. Тайм-аут не
подменяется большим RTT и не объявляется нарушением без известного порога.
При неполном окне, пропусках или временном разрыве больше `--max-gap-seconds`
(по умолчанию 2) селектор воздерживается. После abstention его состояние
сохраняется; удержание измеряется индексами samples. Текущий timeout ещё не
известен при решении и может сделать выбранный outcome недоступным.

Ресемплирования нет. Горизонты — **измерения, не секунды**. Изменение допустимого
разрыва не калибрует модель под другую частоту. `--allow-domain-shift` только
подтверждает осознание ограничения; переносимость на реальные данные не доказана.
Среднее/p95/SLA считаются только по доступным выбранным исходам; coverage и
abstentions нужно читать вместе с ними. Недоступные исходы не означают успех.
Контрфактический минимум вычисляется только при известных обоих путях.

## Что показывает Atlas

Вход — локальный JSON-массив одного measurement/probe/destination (не менее
10 наблюдений). Файл не скачивается автоматически и не поставляется в Git.
RTT наблюдения — медиана успешных packet RTT; невалидные/неуспешные packet
results считаются отдельно. Все тайм-ауты сохраняются; это не метрика полного
распределения задержек с потерями. Persistence и train frequency оцениваются
на последних 20% origins при доступных текущем и предыдущем RTT. Данные не
используются для обучения двухканальной нейросети. Один путь не позволяет
оценить выбор между реальными каналами, тем более каналами целевого объекта.

Проверенный локальный файл: 2520 наблюдений, 7560 packet results без невалидных
RTT; медианный интервал 240 с (237–244 с). В тесте 504 доступных origins,
0 превышений 100 мс, mean 6.907857246 мс, p95 7.48587325 мс,
persistence MAE 0.339018351 мс. Нулевые Brier обеих baseline при отсутствии
событий не доказывают полезность предупреждений; recall здесь null.

## Проверенный suite

4000 samples, 40 эпох максимум, seeds 41/42/43, 800 тестовых шагов на запуск.
Для каждого запуска coverage=1, abstentions=0; сохранённая модель согласована
с пакетной оценкой. Ниже mean/p95 в мс, сырая доля RTT>100 и переключения:

- normal 41: 71.741129 / 88.540060; 0.625%; 12 переключений.
- normal 42: 75.473688 / 96.152357; 2.875%; 10 переключений.
- normal 43: 76.474561 / 95.009288; 1.500%; 21 переключение.
- shared-stress 41: 96.774665 / 113.621101; 31.500%; 12 переключений.
- shared-stress 42: 100.447766 / 120.630026; 42.750%; 14 переключений.
- shared-stress 43: 101.294482 / 119.266411; 46.250%; 21 переключение.

Во всех шести запусках mean RTT и сырая доля нарушений risk-selector хуже,
чем у previous-RTT baseline. Нижняя граница сырых нарушений из одновременного
превышения обоих путей в shared-stress: 30.375%, 40.625%, 43.625%.
Полные метрики всех политик, effective RTT и provenance — в локальных JSON.
Это честный отрицательный результат для текущей модели, а не гарантия SLA,
доказательство переноса на реальную сеть или оценка QKD/PTP/boundary clocks.
