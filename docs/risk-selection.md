# Выбор пути с учётом риска

`feat/risk-aware-selection` основана на `feat/degradation-warning`.

```bash
uv run quantum-link risk-experiment --seed 42 --scenario normal --output artifacts/risk-42
uv run quantum-link risk-experiment --seed 43 --scenario shared-stress --output artifacts/risk-stress-43
```

Модель предупреждений остаётся прежней. Для решения в t используются её
P(RTT(t)>100) (горизонт 1) и прогноз RTT(t), полученные только по истории до t−1.
Горизонты 5/15/60 служат диагностике раннего предупреждения; их нельзя выдавать
за вероятность нарушения именно на следующем шаге. Вероятности не калиброваны.

## Целевая функция и ограничения

Для кандидата c минимизируется ожидаемая условная стоимость в миллисекундах:

`J(c) = predicted_rtt_ms(c) + violation_penalty_ms * p(c) + switching_cost_ms * I(c != current)`.

Это явно заданная линейная полезность, **не** гарантия SLA и не оценка реальной
стоимости нарушения. `--violation-penalty-ms 100` означает готовность заплатить
100 мс условной стоимости за единицу вероятности нарушения (10 мс за снижение
риска на 0.1). Так RTT участвует как tie-break и как самостоятельная стоимость.
Параметры задаются до теста, а не оптимизируются на нём. Для другого операционного
предпочтения их нужно согласовать с оператором либо выбрать на независимой val.

Первое назначение бесплатно. Переключение разрешено, если:
- с прошлого назначения прошло не меньше `--min-hold-samples` (по умолчанию 5);
- улучшение J строго больше `--hysteresis-ms` (3 мс).

Стоимость `--switching-cost-ms` (3 мс) входит и в J, и в effective RTT при оценке.
Внутри hold даже высокий риск не вызывает переключения: это жёсткое ограничение,
в том числе потенциальный источник ухудшения SLA. При равенстве сохраняется путь,
а при первом назначении выбирается путь 0. Состояние сбрасывается перед тестом.

## Оценка

Все 20% тестовых строк участвуют в выборе, в том числе последние 59: их h=1
цели доступны для оценки без пересечения границы. Модель не переобучается.
Сравнения: фиксированные пути, предыдущий RTT со стоимостью переключения,
недостижимый поточечный oracle по фактическому RTT (только оценка).
Последний не оптимизирует стоимость переключения и не является оптимумом
полной J. Минимальная возможная частота сырых нарушений — доля строк, где
**оба пути** превышают 100 мс; она явно записана в отчёте.

`risk-report.json` содержит mean/p95 RTT, SLA, effective RTT, effective SLA,
число переключений по всем тестовым строкам без исключения неудобных случаев.
`risk-decisions.csv` сохраняет прогнозы и решения. `normal` использует исходный
генератор, `shared-stress` прибавляет 25 мс обоим путям **на всём ряду до split**.
Это два заранее объявленных синтетических сценария, не настоящая сеть.
Сравнение нескольких seeds не заменяет независимые реальные измерения.
Превосходство над предыдущим RTT не предполагается и не гарантируется.
