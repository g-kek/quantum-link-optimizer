# Прогноз задержки и превышения цели

## Запуск

```bash
uv run quantum-link forecast --output artifacts/forecast-01
uv run quantum-link forecast --input data/ping.csv --output artifacts/forecast-csv
```

Без `--input` строится синтетическая неделя из 10 суток с шагом 10 с
CSV — тот же формат, что у [`diagnose`](../guide/diagnosis.md), берутся пробы до `endpoint`,
`load_percent` и timeout становятся признаками загрузки и потерь

## Что прогнозируется

Для каждого пути на 1, 5 и 15 минут вперёд

- Диапазон RTT в момент t+h: p10, медиана и p90
- Вероятность, что в (t, t+h] будет минута с медианой RTT выше цели

Признаки берут только прошлое: медианы за 1/5/15 минут, p90, минимум, тренд RTT,
загрузку, потери и их тренды, запас ключей и время до его исчерпания,
время суток, выходной и RTT в то же время вчера
Пропуски заполняются медианой train и получают отдельный флаг

## Модель

Небольшая сеть, два слоя по 64, учит поправку к логарифму медианы за 5 минут
Квантили упорядочены по построению, потери — pinball по логарифму и BCE
40 эпох, лучшая эпоха по validation, разбиение по времени 60/20/20 с зазором в горизонт
Интервал получает конформную поправку на validation, вероятность — калибровку Платта,
порог тревоги выбирается по F1 на validation, всё одинаково для сети и простых правил

Простые правила для сравнения: последнее значение, медиана за 5 минут
и то же время вчера, у каждого полоса ошибок из train

## Синтетическая неделя

Нагрузка рабочего дня ведёт очередь, всплески нарастают 15 минут,
путь деградирует за 1–2 часа, пул ключей тает при слабой генерации,
внезапные ступени маршрута приходят без предвестников
Числа иллюстративные, это проверка метода, а не модель сети оператора

## Результат на последних двух сутках

Горизонт 5 минут, оба пути

| Метод | Ошибка медианы | Покрытие 80% | Ширина полосы | Brier | AUC | Предупреждено | Ложных в сутки |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Сеть | 4,0 мс | 81% | 13,8 мс | **0,008** | **0,997** | **22 / 25** | 10 |
| Последнее значение | 5,7 мс | 80% | 27,0 мс | 0,018 | 0,935 | 11 / 25 | 82 |
| Медиана 5 минут | 3,9 мс | 80% | 20,1 мс | 0,019 | 0,922 | 0 / 25 | 0 |
| То же время вчера | 6,3 мс | 80% | 31,6 мс | 0,047 | 0,877 | 9 / 25 | 110 |

Медианное упреждение сети на 5 минут — 205–250 с по путям, у последнего значения 10–15 с
На 15 минут сеть предупредила 23 из 25 превышений, Brier 0,014 против 0,032

По причинам превышения, горизонт 5 минут

| Причина | Предупреждено |
| --- | ---: |
| Рост нагрузки | 18 / 18 |
| Исчерпание ключей | 3 / 3 |
| Внезапная ступень | 0 / 1 |
| Фон без эпизода | 1 / 3 |

Точность медианы у сети такая же, как у медианы за 5 минут,
выигрыш — в узкой откалиброванной полосе и в вероятности превышения
Внезапные ступени не предсказываются, их нужно быстро обнаружить
[детектором ступеней](../validation/diagnostics.md)

## Отличие от прежних опытов

Прежняя MLP предсказывала опоздание команды на стенде через 250 мс,
где сбои начинаются ступенькой без предвестников, поэтому не обогнала EWMA
Прежний `warning-experiment` на синтетике без загрузки замечал превышение за 1–3 отсчёта
Здесь горизонт в минутах и есть признаки, которые меняются раньше задержки

Для сети оператора нужны 2–4 недели RTT обоих путей с шагом 1–10 с
и загрузка каналов за то же время, без загрузки останутся только суточный ритм и тренды
