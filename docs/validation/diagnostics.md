# Точность диагностики

## Запуск

```bash
uv run python -m quantum_link_optimizer.experiments.diagnostics.run \
  --plan lab/experiments/diagnostics.json --output artifacts/experiments/diagnostics-01 \
  --baseline artifacts/experiments/pipelining-01/final
uv run python -m quantum_link_optimizer.experiments.diagnostics.run \
  --plan lab/experiments/diagnostics-heldout.json \
  --output artifacts/experiments/diagnostics-heldout-01
```

`--baseline` переоценивает журналы прошлых прогонов тем же счётчиком
Восемь сценариев × четыре seed, EWMA и восемь команд в полёте

## Что считается

Сценарий объявляет ожидаемые инциденты: класс, путь, момент начала и истинный компонент
Один инцидент считается один раз, точки времени отдельно не оцениваются

| Сценарий | Ожидается | Компонент |
| --- | --- | --- |
| normal, receiver-restart | Ничего | — |
| swap | Деградация A с начала, B после смены | Участок A, затем B |
| common-700 | Деградация A+B | Не задан: задержки независимы |
| shared-queue | Деградация A+B | Общий участок |
| loss-a | Деградация A | Участок A |
| slow-kms | Медленная выдача ключей | KMS |
| key-exhaustion | Пустой пул после исчерпания | KMS |

Ложное срабатывание — открытый инцидент, которого нет в ожидаемых и который не следует
из основного сбоя: очередь отправителя при медленных путях или ступень RTT при включении
перегрузки, путь с RTT у цели по конфигурации тоже не считается сбоем

## Результат

| Метрика | Старые правила, 16 эпизодов | Новые, seeds настройки | Новые, отложенные seeds |
| --- | ---: | ---: | ---: |
| Найдено инцидентов | 13 / 14 | 27 / 28 | 27 / 28 |
| Компонент назван верно | 0 / 11 | 23 / 23 | 23 / 23 |
| Ложных срабатываний на эпизод | 3,13 | 0,19 | 0,19 |
| До обнаружения, медиана / p90 | 50 / 225 мс | 50 / 692 мс | 49 / 677 мс |

Старые правила не указывали компонент, почти все ложные — «медленный получатель»
от абсолютного порога 1 мс при обычной выдаче ключа получателю
Отложенные seeds 4001–4013 не использовались при настройке правил

Оставшиеся ошибки: loss-a иногда открывает деградацию A повторно, одна потеря из четырёх
находится позже горизонта, в receiver-restart два раза открылась ступень RTT
p90 времени обнаружения растёт из-за потерь: нужно не меньше шести проб в окне

## Изменения правил

- Пороги получателя и KMS считаются от нормы сигнала: медиана, MAD и 1,5 × p99,
  а значения выше 20–25% бюджета SLO в норму не попадают
- Ступень RTT по CUSUM открывает `path_change`, ступень вниз — восстановление
- Доля timeout от 15% за свежее окно — деградация пути
- Одна команда в очереди при восьми в полёте больше не считается перегрузкой
- В первые секунды запуска отсутствие данных не открывает инцидент
- Вывод получает класс, домен по ITU-T Y.3804, действие и вероятный компонент

Метрика KMS в испытаниях #7 учитывала только ожидание ключа, пустой пул записывался как
пропуск, отсюда полнота около 21%, на текущих правилах сигнал есть в slow-kms 108/108,
в key-exhaustion 90/108 решений

## Границы

Сценарии стенда простые, сбой один за раз, компоненты известны заранее
Точность на сети оператора нужно мерить по журналу аварий с подтверждёнными причинами
QKD-классы — рост QBER и падение генерации — заведены, но без данных не проверяются
