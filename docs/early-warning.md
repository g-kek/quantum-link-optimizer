# Раннее предупреждение: протокол

Ветка `feat/degradation-warning` продолжает `feat/rtt-forecasting`.
Команда `uv run quantum-link warning-experiment --output artifacts/warning-42`
сохраняет `warning-model.pt`, `warning-report.json`, `warning-predictions.csv`
и исходную синтетическую телеметрию. Старые команды не изменены.

## Цель и хронология

Для каждого пути и горизонта h = 1, 5, 15, 60 **измерений** модель оценивает
событие «хотя бы один RTT строго больше 100 мс в [t, t+h)».
Это не вероятность непрерывного нарушения в течение h шагов и не прогноз
времени начала. Регрессия отдельно предсказывает RTT(t). Вход — 16 наблюдений
до t, последнее t−1. В синтетике шаг равен условной секунде; при другой
частоте измерений горизонт не становится тем же количеством секунд.

Разбиение 60/20/20 по времени. На каждом участке удаляются последние 59
возможных origins: **все 60 целевых строк должны оставаться внутри участка**.
Одинаковые origins используются для всех горизонтов, включая h=1.
История может пересекать левую границу: это уже известные наблюдения.
Scaler обучается только на первых 60% строк. Небольшая CPU MLP (32 ReLU)
обучается AdamW: MSE стандартизованного RTT + BCE, равные веса блоков,
без балансировки классов. Лучшая эпоха выбирается по val loss. Порог 0.5
задан заранее, не выбран по test. Вероятности не объявляются калиброванными.

## Предупреждения и знаменатели

Инцидент — максимальная последовательность RTT >100; onset — её первая
строка. Для каждого пути сигнал разрешён, только если последнее наблюдение
не нарушало SLA. Alarm episode начинается на переходе разрешённого сигнала
из false в true. Одна непрерывная серия сигналов не создаёт много тревог.

Eligible onset — начало, для которого есть хотя бы один оцениваемый origin t
с известным хорошим t−1 и t ≤ onset < t+h. Начала без такой возможности
не входят в recall (например, инцидент, уже начавшийся до теста). Границы
origins и последней целевой строки записаны в отчёте; это **не все строки теста**.
По времени каждая тревога сопоставляется первому ещё не сопоставленному
eligible onset в её будущем окне. Каждому началу и каждой тревоге соответствует
не более одной пары; повторная тревога об уже найденном начале — ложная.
Это офлайн-оценка; будущие события не участвуют в генерации тревоги.

Precision = пары / эпизоды тревоги; recall = пары / eligible onsets.
Ложные тревоги = эпизоды − пары; частота — на 1000 оцениваемых origins путей
(2 × число origins, включая запрещённые сигналы). Lead = onset − (t−1),
то есть от последнего доступного измерения, в samples; минимум 1.
Пустые знаменатели и lead без пар представлены JSON null, отдельно no_events.
Метрики объединяют оба пути, но сопоставление выполняется отдельно.

Для каждого горизонта сравнивается Brier score модели, persistence (последнее
нарушение как постоянный прогноз на всё окно) и частоты событий из purged train.
Постоянная train frequency также проходит тот же алгоритм тревог. Большой
горизонт часто имеет большую базовую частоту: хорошие цифры не обязательно
означают полезное раннее обнаружение. Ни одного измерения целевых каналов
в этом эксперименте нет; пригодность для QKD/PTP не установлена.
