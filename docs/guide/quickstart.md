# Запуск, входные данные и отчёт

Версия 0.2.0. Это исследовательский инструмент; данные целевых каналов пока не предоставлены.

## Готовый сценарий показа

```bash
uv sync --locked --python 3.12
uv run quantum-link demo --output artifacts/demo
```

Откройте `artifacts/demo/index.html` непосредственно в браузере. Отчёт работает
как локальный файл, без backend, CDN, Node.js и подключения к интернету.
Для просмотра результата обучение повторять не нужно: достаточно HTML-файла.

Показ на 5–7 минут:

1. Обратить внимание на маркировку синтетики и порог 100 мс.
2. Показать график двух путей и долю их одновременных превышений.
3. Выбрать previous RTT, EWMA, прогноз ML и risk selector; сравнить метрики.
4. Нажать «Воспроизвести», остановить, перемещать ползунок и разобрать причину решения.
5. Выбрать Oracle и объяснить, почему это недостижимый ориентир с доступом к исходам.
6. Скачать JSON, раскрыть сведения о запуске и происхождении данных.
7. Открыть отчёт другого сценария через «Открыть отчёт JSON».

### Сценарии

| Параметр `--scenario` | Что моделируется |
| --- | --- |
| `high-rtt` (по умолчанию) | Базовый генератор +625 мс на обоих путях; оба выше порога |
| `normal` | Некалиброванные базовые RTT 66/73 мс, дрейф и эпизоды нагрузки |
| `shared-stress` | Базовый генератор +25 мс на обоих путях |

Сдвиги применяются ко всему ряду до обучения, это не тест внезапного domain
shift. Ни один сценарий не откалиброван под сеть РЖД. `high-rtt` показывает
ограничение метода, а не доказанное объяснение исходных 700 мс.

```bash
uv run quantum-link demo --scenario normal --output artifacts/demo-normal
```

Настройки: `--samples 4000 --seed 42 --epochs 40`. Для короткой технической
проверки можно использовать 500 samples и 2 эпохи; её метрики не заменяют
полный эксперимент. Слишком короткий ряд отклоняется из-за горизонта 60.

## Показ реального лабораторного обмена (#6–8)

Для показа команд, очереди и KMS используйте отчёт из завершённых UDP/TCP-опытов.
Он отличается от приведённого выше генератора RTT. Сначала выполните
[development](../research/forecast-benefit.md), затем
[независимую серию](../validation/independent-trials.md). Сбор занимает несколько
минут; новые каталоги обязательны. Обучение происходит только в development.

```bash
uv sync --locked --python 3.12 --extra lab
uv run python -m quantum_link_optimizer.experiments.demo.build \
  --development artifacts/experiments/forecast-benefit-01 \
  --validation artifacts/experiments/independent-trials-01 \
  --output artifacts/experiments/operator-demo
```

Откройте `artifacts/experiments/operator-demo/index.html` как локальный файл.
HTML самодостаточен; сеть, Python и модель для его просмотра не нужны.
Рядом сохранён `demo-data.json`. Сборщик отклоняет повреждённые manifest,
несовпадающую модель/lock и изменение snapshot кода между final-эпизодами.

Показ на 5–7 минут:

1. Прочитать результат: преимущество прогноза не подтверждено; бюджет для
   1024 прикладных байт остаётся непроверенным.
2. Выбрать смену быстрой ветви и EWMA, затем прогноз: RTT проб, исходы команд,
   наблюдения и основания решения показаны на одной шкале.
3. Включить воспроизведение: до записи исхода в журнале его нет на графике.
   Сводные счётчики относятся ко всему эпизоду.
4. Выбрать slow KMS, исчерпание ключей, общую очередь и рестарт. Посмотреть
   запас из KMS API, локальную очередь, ожидание ключа sender/receiver и отказы.
   Измеренные spans могут перекрываться; это не полная декомпозиция обработки.
5. Раскрыть внесённые воздействия. Это ground truth стенда, скрытая от
   контроллера; его диагноз может остаться `not_established`.
6. Сравнить полные знаменатели, цену копий и overhead. Скачать JSON и проверить
   раздел происхождения: модель, freeze, snapshots и ограничения опыта.
7. Разобрать вопросы оператору в конце отчёта: границы услуги и топология,
   общие ресурсы, пробы и SLO, очереди/errors/drops, API KMS/QKD/PTP, MTU,
   идемпотентность и разрешённые действия/откат. Материал ключей не запрашивается.

Новые результаты — [польза прогноза](../research/forecast-benefit.md) и
[независимые испытания](../validation/independent-trials.md). Для объяснения
погоды, помех, атак либо старения нужны дополнительные внешние свидетельства.
Отчёт не объявляет высокий RTT или ожидание KMS доказанной физической причиной.

## Внешняя телеметрия

```bash
uv run quantum-link audit --input data/ping.csv --output artifacts/ping-audit
```

`audit` не обучает ML и не загружает модель с синтетики. Он описывает измерения,
оценивает предел выбора и сравнивает fixed-path, previous RTT и EWMA.
Результат — `index.html` и `report.json`.

UTF-8 CSV, точный порядок заголовков:

```text
sample,timestamp,path,status,rtt_ms,source,provenance
```

| Поле | Требование |
| --- | --- |
| `sample` | Последовательный целый индекс; один sample объединяет пробы путей |
| `timestamp` | ISO 8601 с часовым поясом; строго возрастает между samples |
| `path` | 0 или 1; максимум одна строка каждого пути на sample |
| `status` | `ok`, `timeout` или `missing` |
| `rtt_ms` | Положительный конечный RTT при `ok`; иначе пустое поле |
| `source` | `real_telemetry` или `ripe_atlas` |
| `provenance` | Непустое описание точек, метода и происхождения измерений |

У путей одного sample должны совпадать timestamp и source. Если строки одного
пути нет, его исход считается missing. Сохраняйте сырые времена проб отдельно:
при подготовке парного CSV нужен описанный допуск синхронизации, а не выдуманное
равенство реально различных времён. Не копируйте один путь во второй и не
объявляйте синтетику реальными измерениями ради прохождения схемы.

Нужно минимум два момента времени. Оцениваются все samples, кроме первого,
который нужен для истории. Внешний `source` — заявление поставщика файла,
не автоматическая проверка того, что данные пришли от оператора.
В репозитории нет реального двухканального набора МКС РЖД.

### Частота и пропуски

По умолчанию `--max-gap-seconds 2`. Previous RTT и EWMA воздерживаются при
устаревшей или неполной предыдущей паре. После разрыва EWMA начинает новое
накопление; состояния удержания селекторов сохраняются. Fixed-path продолжает
выбирать назначенный путь. Это может давать разное покрытие: сравнивать одни
средние без coverage некорректно.

Для пятиминутных проб, например, явно задайте допустимый интервал:

```bash
uv run quantum-link audit --input data/ping.csv \
  --max-gap-seconds 330 --output artifacts/ping-audit
```

Здесь нет секундной нейросети или переноса её горизонтов: только baseline по
прошлым наблюдениям. Тайм-аут не заменяется большим числом и не считается
успехом. Порог timeout отсутствует в текущей схеме, поэтому неизвестный RTT
не объявляется известным нарушением SLA; число таких исходов выводится отдельно.

## Как читать отчёт

- **Оба пути выше порога** — доля известных пар, где min(RTT0, RTT1)>SLA.
  Это нижняя граница сырых нарушений на этих парах при выборе одного пути,
  без затрат переключения. Покрытие пар показывается рядом.
- **p95 лучшего из двух RTT** — квантиль минимума фактических RTT на доступных
  парах; ориентир с доступом к исходам, не исполнимый алгоритм.
- **Mean/p95/p99 и доля превышений** — по известным выбранным RTT.
  Покрытие, тайм-ауты, missing и отказы читать вместе с ними.
- **Отказ** — рекомендация не выдана; это не успешная доставка.
- **Переключение** — смена рекомендации между назначениями. Затраты условные,
  реального сетевого действия нет. Полные effective-метрики доступны в JSON.

Таблица всегда относится ко всему периоду оценки; ползунок меняет раскрытую
часть графика и отдельное решение, но не пересчитывает общие метрики.
Перемещение ползунка — визуализация уже рассчитанного офлайн replay.

Для синтетики используются финальные 20% временного ряда. Модель обучается
на первых 60%, эпоха выбирается по следующим 20%; scaler не видит тест.
Решение использует историю до t−1. Для demo сверяется совпадение сохранённого
replay с batch на каждом шаге. Oracle явно выделен: он использует исход t.

Сопоставимые политики `previous_rtt_constrained`, `ewma_constrained`,
`nn_rtt_constrained` и `risk_selector` имеют одинаковые hold/гистерезис/затраты.
У первых трёх нет вероятностного штрафа. Старый `previous_rtt_selector`
оставлен как baseline без удержания и гистерезиса.

## Артефакты и воспроизводимость

`report.json` содержит runtime, commit SHA, признак локальных изменений,
конфигурацию, SHA-256 входа, а для demo также SHA-256 модели, метрики и решения.
Из установленного пакета вне Git commit может быть неизвестен — поле будет null.

В `experiment/` demo сохраняет телеметрию, checkpoint, отчёты предупреждений
и выбора, CSV решений и `replay/shadow.jsonl`. Checkpoint имеет версию схемы;
при загрузке проверяются scaler, горизонты, границы и конечность весов.
Загружайте только собственные или доверенные checkpoint.

Одинаковые seed, данные и окружение воспроизводят вычисления. Идентичность
между версиями библиотек и архитектурами не гарантируется. Метаданные commit
могут отличаться между запусками, даже если численные результаты совпали.
Повторный запуск в тот же каталог перезаписывает его файлы.


Для лабораторной передачи см. [команды и ключи](../lab/commands-and-keys.md); ограничения пилота и источники — в [контексте](../research/context-and-sources.md).
