# Разбор RTT

## Запуск

```bash
uv run quantum-link diagnose --input data/ping.csv --distance-km 1200 \
  --output artifacts/diagnosis
uv run quantum-link diagnose-examples --output artifacts/diagnosis-examples
uv run quantum-link breakdown --run artifacts/experiments/pipelining-01/final/swap-1009-ewma
```

`diagnose` раскладывает RTT каждого пути и называет вероятную причину
`diagnose-examples` прогоняет восемь синтетических наборов с известной причиной
`breakdown` делит задержку команд стенда по этапам от поступления до ACK

## CSV

Первые семь колонок совпадают с форматом `audit`, дальше можно добавить любые из четырёх

```text
sample,timestamp,path,status,rtt_ms,source,provenance,packet_bytes,probe,target,load_percent
```

| Поле | Значение |
| --- | --- |
| `packet_bytes` | Размер ping, например 64, 512 и 1400 |
| `probe` | `icmp`, `udp`, `tcp` или `stamp`, по умолчанию `icmp` |
| `target` | Точка измерения: `gw`, `hub`, `endpoint`, по умолчанию `endpoint` |
| `load_percent` | Загрузка канала в момент пробы, 0–100 |

`path` принимает 0/1 или A/B, `source` — `real_telemetry`, `ripe_atlas` или `synthetic_example`
Одна строка — одна проба, пара (sample, path, target, probe, packet_bytes) уникальна
Порядок точек вдоль пути можно задать через `--targets gw,hub,endpoint`

## Составляющие

| Составляющая | Как считается |
| --- | --- |
| Базовая | Скользящий минимум за 10 минут или 10 интервалов проб |
| Очередь | RTT минус базовая, медиана и p95 |
| Сериализация | Наклон нижнего дециля RTT от размера пакета |
| Обработка ICMP | Разница нижних децилей ICMP и UDP/TCP до той же точки |
| Распространение | Оценка `2 × расстояние × 1,4 × 5 мкс/км`, если задан `--distance-km` |
| Участки | Разность RTT до соседних точек одного пути |
| Общий участок | Корреляция очередей A и B по одинаковым sample |
| Форма | Ступени базовой задержки, суточный профиль, два устойчивых уровня |

## Причины

| Класс | Основание |
| --- | --- |
| Очередь | Большая доля очереди, связь с загрузкой, суточный пик |
| Узкая полоса | Значимый рост RTT с размером пакета |
| Медленная обработка ICMP | ICMP заметно медленнее UDP/TCP до той же точки |
| Постоянная задержка | Высокая базовая часть, которую не объясняют размер и ICMP |
| Смена маршрута | Ступень базовой задержки |
| Мигание маршрута | Два устойчивых уровня и частые переключения |
| Потери и повторы | Доля timeout от 1% |

Оценка от 0 до 1, от 0,6 — «вероятно», от 0,3 — «возможно»
Если очереди A и B растут вместе, причина относится к общему участку
Отчёт перечисляет, каких замеров не хватило для уверенного вывода

## Примеры

Восемь наборов по суткам с шагом 10 с: норма, очередь, узкая полоса, ICMP,
постоянная задержка через удалённый узел, смена маршрута, мигание и общая очередь
Все восемь определяются верно, это проверка правил, а не точность на сети оператора

## Этапы команды

`breakdown` читает `sender.jsonl` прогона и для каждой команды выделяет
опоздание генератора, очередь Router, ожидание ключа, отправку, сеть и повторы,
очередь, ключ и исполнение у получателя и обработку ACK
Сеть и повторы — остаток после измеренных отрезков
Сводка показывает обычные команды, хвост от p95 и опоздавшие

На прогонах #7 до исправления очереди хвост normal/fixed B: 477 мс очереди Router
из 563 мс, loss-a/fixed A: 723 мс из 803 мс
После [исправления](../validation/pipelining.md) в slow-kms/EWMA хвост 479 мс:
ожидание ключа у отправителя 204 мс, у получателя 182 мс, очередь получателя 35 мс
