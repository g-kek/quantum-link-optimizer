# План развития

## Текущее состояние

- Linux-стенд A/B, общий bottleneck, управляемые сбои и PCAP
- AEAD-команды, TCP KMS, bounded queues и SQLite dedup
- Телеметрия, датасеты, freeze и независимые испытания
- EWMA, ограниченные копии, pacing и базовая диагностика
- Офлайн-отчёт по событиям и результатам

ML не показал убедительного преимущества, полный бюджет 1024 байта/1 мс не подтверждён

## Сущности

| Группа | Назначение |
| --- | --- |
| Site / Node / Device / Interface | Площадки, оборудование и порты |
| Link / Queue | Направленные участки, очереди и классы |
| Path / Tunnel | Последовательность участков, отдельно туда и обратно |
| Dependency group | Общие ресурсы и подтверждение зависимости |
| Service / Flow | SLO, класс трафика, порядок и разрешённые действия |
| Message / Attempt / Copy / Packet | Работа, попытка, копия и наблюдаемый пакет |
| Observation | Значение, единица, источник и времена |
| Incident / Hypothesis / Evidence | Инцидент, гипотеза, основания и альтернативы |
| Policy / Decision / Action | Правило, решение и действие с откатом |
| Episode / Dataset / Model | Опыт, данные и версия модели |

Переход A→B→A для одного пакета требует многосегментного графа
Пример: `S → A1 → A2 → B3 → B4 → A5 → R`
Нужны реальные соединения между участками, MTU, обратный маршрут и отсутствие циклов
Текущий выбор A/B между командами этого не реализует

## Порядок работ

| Этап | Что добавить | Критерий |
| --- | --- | --- |
| M0 | Контракт сервиса, SLO и capabilities | Ясно, чем можно управлять |
| M1 | История нагрузки, очередей, потерь и качества | Счётчики сходятся на концах |
| M2 | Версионированный граф, многосегментный стенд и часы | Путь подтверждён capture |
| M3 | Инциденты и диагностика по участкам | Причина имеет свидетельства и альтернативы |
| M4 | Прогноз задержки/очереди/ключей | Есть независимая польза доставки |
| M5 | Приоритеты, распределение, admission и откат | Измерены эффект, стоимость и fairness |
| M6 | Read-only KMS/QKD/PTP, ИБ, оптика и обслуживание | У гипотез есть внешние подтверждения |
| M7 | Полный performance-контракт и операторский пилот | Пройдены SLO и условия отката |

M0 → M1 и каталог M2 → стенд M2 → M3/M5 → M7
M4 опционален, M6 зависит от доступных API
Overhead измеряется с ранних этапов, пилот идёт read-only → shadow → управление

## Данные

- Нагрузка: предложено, допущено, отправлено, исполнено, goodput и байты копий
- Очереди: backlog, время ожидания, drops, лимиты и класс
- Потери: timeout, late, reorder, duplicate и unknown отдельно
- Источники: время измерения/доставки, clock domain, freshness и reset
- Причины: конфигурация, аварии, оптика, температура, питание и обслуживание

Погода, помехи, атаки и старение не определяются по одному RTT
Неточные или отсутствующие данные сохраняются как unknown
