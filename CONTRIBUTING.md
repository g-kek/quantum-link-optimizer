# Разработка

## Окружение

```bash
uv sync --locked --python 3.12
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
uv build --wheel
```

Поддерживаются Python 3.12 и 3.13. Основная ветка — `main`. Создавайте короткие
ветки от неё; исторические `feat/*` фиксируют предыдущие этапы проекта.

## Изменения и коммиты

Один коммит — одна проверяемая задача. Используйте короткие сообщения с
префиксом `feat:`, `fix:`, `docs:`, `refactor:`, `test:` или `chore:`.
Объясняйте причину нетривиального изменения в теле коммита или PR.
Не смешивайте форматирование всего проекта с функциональным исправлением.

Для изменения поведения добавьте проверку реального риска: утечки будущего,
исчезновения события после timeout, неверного знаменателя или переключения.
Документация должна описывать итоговое поведение. HTML-шаблон находится в
`src/quantum_link_optimizer/templates/report.html`; проверяйте его в браузере
на desktop и узком экране. Итоговый HTML должен работать как локальный файл.

## Данные и методика

Не коммитьте окружение, сырые операторские данные, веса и результаты обучения.
Для небольших проверок используйте fixtures с явно указанным происхождением.
Не называйте синтетику измерениями МКС. Не удаляйте тайм-ауты ради улучшения метрик.

Сохраняйте временные разбиения, scaler только по train и границу информации
в решении t. Настройки выбирайте до финального теста; oracle оставляйте только
для оценки. При изменении знаменателей, схемы отчётов или checkpoint обновляйте
методику и версию соответствующего формата.
